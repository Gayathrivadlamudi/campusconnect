App architecture means organizing the code so that it will be easier to debug or do the changes
it will be easy to test and maintain

so what does good architecture does
maintainability : app architecture makes it easier to modify,update and fix issues easily
 better user experience - Features can ship faster and with fewer bugs.
 Lower cognitive load - Developers who are new to the project will be more productive in a shorter amount of time,
 and code reviews are generally less time-consuming when code is easier to understand.



 Flutter App Architecture
 1)separation of concerns:we divide the application into different components based on their responsibility
 Example:
 - View → Displays UI.
 - ViewModel → Handles UI-related logic.
 - Repository → Handles data operations.
 - Service → Communicates with Firebase/API.

 2)Layered Architecture
   Definition: Dividing an application into layers based on their responsibilities.

   Remember these three layers:
   Layer	Responsibility
   UI	Displays information and handles user interactions
   Logic	Handles business and presentation logic
   Data	Fetches and stores data

   Example: When a user updates their profile:
   1. UI collects the details.
   2. Logic validates them.
   3. Data layer updates Firestore.

3. Single Source of Truth (SSOT)
Definition: Maintaining one authoritative source for a particular type of data.
Imagine your application has student information:
Student Name: Ravi
Phone: 9876543210
Department: CSE
Suppose you store this information independently in three different classes:
- ProfileScreen
- DashboardScreen
- ProfileViewModel
Now the student changes their name from Ravi to Rahul.

But you update only the ProfileScreen.

Your DashboardScreen might still display Ravi!

This creates inconsistent data.
How does Single Source of Truth solve this?
Use a Repository to manage the authoritative student profile data.

4)Extensibility: design the code structure in a way that adding new feature becomes easy without changing many existing components
Example: Replacing Firebase with a REST API while keeping the ViewModel unchanged.

Benefits: Flexibility, scalability and easier maintenance.
